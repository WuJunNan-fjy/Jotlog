## 五、参考实现：Junan 的 OSS 用法（已核对）

参考项目 `F:\ideaCode\personal\Junan-Website`，三处核心代码：

| 文件 | 要点 |
|---|---|
| `Backend/Junan-common/.../properties/AliOssProperties.java` | prefix `junan.alioss`，四个字段 endpoint / accessKeyId / accessKeySecret / bucketName |
| `Backend/Junan-common/.../utils/AliOssUtil.java` | `new OSSClientBuilder().build(...)` → `putObject(bucket, objectName, new ByteArrayInputStream(bytes))`，finally 里 `shutdown()`；URL 规则 `https://{bucket}.{endpoint}/{objectName}`；另有按扩展名分目录（image/video/audio/...）的 `getFileCategory` |
| `Backend/Junan-server/.../config/OssConfiguration.java` | `@Bean @ConditionalOnMissingBean` 装配 |

- **SDK 版本**：`com.aliyun.oss:aliyun-sdk-oss:3.17.4`（Junan 父 pom 的 dependencyManagement）。Jotlog 直接引这个版本。
- Junan 的凭证全部走环境变量：`ALIOSS_ENDPOINT / ALIOSS_ACCESS_KEY_ID / ALIOSS_ACCESS_KEY_SECRET / ALIOSS_BUCKET_NAME`（见其 `application-docker.yml`）。仓库里没有真值，拿不到，所以 Jotlog 写占位符。

### Junan 实现的两个不足，Jotlog 要避开

1. **每次上传都新建并 shutdown 一个 OSSClient**——客户端是线程安全的、内部带连接池，应当全局单例。
2. 扩展名分类用 `substring(lastIndexOf(".")+1)`，无扩展名文件会炸；Jotlog 本身已用 sha256 内容寻址，**不需要**按类型分目录，别照搬那坨 switch。

## 六、施工方案（下一步照这个做）

### 目标结构

```
com.jotlog.storage
  ├─ StorageService.java          统一门面接口（唯一对外抽象）
  │    record StoredObject(String key, String location)  // key 入 storage_path；location 为本地路径或 OSS URL
  │    StoredObject store(byte[] bytes, String filename, String mime, String sha256)
  ├─ LocalStorageService.java     现有磁盘逻辑搬过来，@ConditionalOnProperty(type=local, matchIfMissing=true)
  └─ OssStorageService.java       OSS 实现，@ConditionalOnProperty(type=oss)
```

要点（含历史经验教训，务必遵守）：

1. **只有一个门面接口** `StorageService`，OSS client 是实现内部细节。不要搞 `FileStorageService` + `OssFileService` 双抽象（历史项目双接口并存导致调用方大面积编译失败）。
2. **OSSClient 做成单例 Bean**（构造一次，`@PreDestroy` 时 shutdown），不要每次上传 new。
3. **对象 key 沿用现有 sha256 内容寻址**：`{sha前2位}/{sha}`（与磁盘两级目录一致，天然去重；文件名只存数据库，不进 key，避开中文/特殊字符问题）。
4. `IngestService` 改为注入 `StorageService`，删掉 `Path storageRoot` 字段和 nio 写入；唯一调用点，直接改签名无兼容负担。
5. `attachments.storage_path` 语义改为"存储对象 key"：
   - local：仍是相对/绝对路径（与现在一致）；
   - oss：存对象 key；访问 URL 由 OSS 实现按 `https://{bucket}.{endpoint}/{key}` 现拼或入库时一并返回。
   - 字段长度 1024 够用，**不需要 Flyway 迁移**。
6. SDK 3.17.4 API 备忘（历史项目因版本不匹配编译失败过）：
   - 上传：`ossClient.putObject(bucket, key, new ByteArrayInputStream(bytes))`，可带 `ObjectMetadata` 设 `contentType`（建议设，否则浏览器下载可能不预览）；
   - 下载（M1 才用）：`GetObjectRequest req = new GetObjectRequest(bucket, key); ossClient.getObject(req, file)`；
   - 删除（M1 才用）：`ossClient.deleteObject(bucket, key)`。
7. 异常处理保持 `IngestService` 现有风格：附件失败只 `log.warn`，不拖垮主记录。OSS 的 `OSSException`/`ClientException` 要在实现内 catch 并记 requestId。

### 配置改造

`src/main/resources/application.yml`（只放占位符，与现有风格一致）：

```yaml
jotlog:
  storage:
    # local=写本机磁盘（默认）；oss=阿里云 OSS
    type: ${JOTLOG_STORAGE_TYPE:local}
    attachment-dir: ${JOTLOG_ATTACHMENT_DIR:./data/attachments}
    oss:
      endpoint: ${JOTLOG_OSS_ENDPOINT:}
      access-key-id: ${JOTLOG_OSS_ACCESS_KEY_ID:}
      access-key-secret: ${JOTLOG_OSS_ACCESS_KEY_SECRET:}
      bucket-name: ${JOTLOG_OSS_BUCKET_NAME:}
```

同步更新 `config/application-local.yml.example`（加注释模板）；`config/application-local.yml` 留给用户自己填，**不要替用户写真值、不要提交**。

`pom.xml` 加：

```xml
<dependency>
  <groupId>com.aliyun.oss</groupId>
  <artifactId>aliyun-sdk-oss</artifactId>
  <version>3.17.4</version>
</dependency>
```

## 七、铁律（沿用，别破）

1. `raw_input` 永不被 UPDATE 触碰。
2. 入库 → 回执 → 异步增强顺序不变；IngestService 同步路径上不能有慢操作——**OSS putObject 是网络调用**，接入真实附件量后若飞书图片走进来，要确认这步是否会撞 3 秒超时；必要时把附件上传挪到异步 worker（M1 评估，本次先留 TODO 注释，不擅自扩范围）。
3. 凭证只进 `config/application-local.yml`（gitignore），仓库里永远只有占位符。
4. 最小差异：本次只动存储，不顺手做上传端点/前端高亮/飞书图片下载。
