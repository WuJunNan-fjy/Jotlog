## 三、今天踩的五个坑（都记在文档里了，别再踩）

### 坑 1：`1191 Can't find FULLTEXT index`

**现象**：`MATCH(raw_input) AGAINST(...)` 报错。
**根因**：MySQL 要求 `MATCH()` 的列与索引定义**完全一致且顺序相同**，
不是"能用索引前缀"。三列联合索引下即使只搜一列也要写全。
**修法**：索引定为 `(raw_input, title, ai_summary)`，查询一律写全三列。

### 坑 2：`NATURAL LANGUAGE MODE` 会静默失效

**实测**：3 条数据搜「沿途」score=0；22 条时 score=1.80。
**根因**：该模式把「出现在 >50% 行里」的 token 当停用词丢掉。
配 ngram 分词器后中文极易触发，**且不报任何错**。
这不是"数据量少的正常现象"，而是**随数据分布随机失效的设计缺陷**。
**修法**：应用层改用 `IN BOOLEAN MODE`（无阈值，行为确定）。

### 坑 3：ngram 会丢掉含 `a`/`i` 的英文词

**这个最要命**：`Java` 被切成 `Ja`/`av`/`va`，三个 bigram **全含 a 全被丢** → 永远搜不到。
而 `Boot`→`Bo`/`oo`/`ot` 不含停用词 → 正常。

**受控实验**（只差一个字母）：

| 词 | 含字符 | 命中 |
|---|---|---|
| `Zaza` | 含 **a** | ❌ 0 |
| `Zeze` | 含 e | ✅ 1 |
| `Zizi` | 含 **i** | ❌ 0 |
| `Zozo` | 无停用字符 | ✅ 1 |

**修法**（已在服务器上执行）：
```sql
SET GLOBAL innodb_ft_enable_stopword = 0;
ALTER TABLE entries DROP INDEX ft_search;
ALTER TABLE entries ADD FULLTEXT INDEX ft_search (raw_input, title, ai_summary) WITH PARSER ngram;
```

⚠️ **`SET GLOBAL` 重启失效，必须写进 `my.cnf`**：
```ini
[mysqld]
innodb_ft_enable_stopword = 0
```

**应用层已加兜底**：全文返回空时降级 `LIKE`，配置丢了只是变慢，不会搜不到。

### 坑 4：`Unsupported character encoding 'utf8mb4'`

**根因**：JDBC URL 里 `characterEncoding=utf8mb4` 无效。
`utf8mb4` 是 MySQL 字符集名，但这个参数走 Java 的 `String.getBytes(charset)`，
Java 里没这个字符集。
**修法**：写 `characterEncoding=UTF-8`。

### 坑 5：飞书 `Client.im()` 返回 null（NPE）

**现象**：编译过、启动正常、能收消息，**但回执时炸**。
**根因**：`new Client()` + `setConfig()` 只塞了配置，
`im`/`contact`/`bot` 等几十个 service 字段全靠 `Client$Builder.build()` 注入。
**修法**：
```java
Client.newBuilder(appId, appSecret)
      .appType(AppType.SELF_BUILT)
      .openBaseUrl(BaseUrlEnum.FeiShu)
      .build();
```
已加启动自检：`im()` 为 null 直接 log.error。

## 七、铁律（改代码前先看）

1. **`raw_input` 永不被 UPDATE 触碰**——那是用户原话。
   `JdbcEntryRepository.applyAiResult()` 的 SQL 里刻意不出现 `raw_input`。

4. **MATCH 必须写全三列同序**，否则报 1191。
5. **全文检索用 BOOLEAN，不用 NATURAL**。

### 坑 6：`git push` 静默失败（exit 128，零输出）

**现象**：`git remote add` 正常、`git ls-remote` 正常（exit 0），
但 `git push` 一律返回 128，**且 stderr 一行都不打**。查都没法查。

**根因有两层，第二层才是真正的坑**：

1. 系统级 gitconfig（`E:/git/Git/Git/etc/gitconfig`）里的
   `credential.helper=manager`（GCM）在**非交互环境**下起不来，
   它不弹窗也不报错，直接让 git 退出。
   `-c credential.helper=xxx` 覆盖不掉它——它是 multi-valued，命令行 `-c` 只追加。
2. **换成 `store` 也没用**：`git-credential-store` 在 Windows 上是个 bash 脚本，
   要靠 `sh` 子进程跑。本环境下这个子进程同样起不来。
   用 `GIT_TRACE` 才看得见——git 停在
   `run_command: 'git credential-store ... get'` 这一行就没了，stdout/stderr 全空。

**已验证有效的解法**：**根本不启动任何凭据子进程**，
改用环境变量注入 `http.extraHeader` 的 Basic 认证头。

```powershell
$in  = "protocol=https`nhost=github.com`n`n"
$out = $in | git credential fill 2>&1        # 从 GCM 里取已有的 token
$u = ""; $p = ""
foreach ($l in ($out -split "`n")) {
    if ($l -match '^username=(.*)$') { $u = $matches[1].Trim() }
    if ($l -match '^password=(.*)$') { $p = $matches[1].Trim() }
}
$basic = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes($u + ":" + $p))

$env:GIT_CONFIG_NOSYSTEM = "1"          # 屏蔽系统级的 manager
$env:GIT_CONFIG_COUNT    = "1"          # 用环境变量传配置，token 不出现在命令行
$env:GIT_CONFIG_KEY_0    = "http.extraHeader"
$env:GIT_CONFIG_VALUE_0  = "Authorization: Basic $basic"
$env:GIT_TERMINAL_PROMPT = "0"

git push origin main

$env:GIT_CONFIG_NOSYSTEM = $null        # 用完清掉
$env:GIT_CONFIG_COUNT    = $null
$env:GIT_CONFIG_KEY_0    = $null
$env:GIT_CONFIG_VALUE_0  = $null
```

⚠️ 两个 PowerShell 细节，踩过：
- 拼 `$u + ":" + $p` **不能**写成 `"$u:$p"`——PowerShell 会把 `$u:` 解析成作用域修饰符直接崩。
- 用 `GIT_CONFIG_COUNT` 传空值会报 `missing config value`，别塞空项。

**你自己正常推的时候大概率没事**——有桌面会话时 GCM 能弹窗。
这个坑只在 CI / 远程 / 非交互 shell 里出现。

**排不出来的时候**，用这个把 git 的内部日志写到文件（stderr 会被吞）：
```powershell
$env:GIT_TRACE = "C:/绝对路径/trace.txt"; git push origin main
```

**一劳永逸**：配 SSH key 推 `git@github.com:WuJunNan-fjy/Jotlog.git`，
或 `git config --global credential.helper manager-core`（manager-core 不依赖 UI）。
