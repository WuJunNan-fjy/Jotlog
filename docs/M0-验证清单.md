# M0 验证清单：把飞书这条路走通

> 目标：一条飞书消息 → 落进 MySQL → 收到回执
> 预计耗时：30 分钟（其中大部分是飞书后台配置）
> 不涉及 AI、不涉及部署

> **⚠️ 2026-10-08 补充：这份清单写于还没有鉴权的时期。**
> 现在 `/api/**` 全部要登录，直接 `curl` 会拿到 401。
> 要么先在浏览器登录、再从 DevTools 里把 token 抠出来带上：
> ```bash
> curl -H "Authorization: Bearer 你的token" http://localhost:8080/api/entries
> ```
> 要么直接用前端界面验证（http://localhost:5173），接口不用自己敲。
> 飞书链路那几步（发消息 → 回执 → 查库）不受影响，那不走 HTTP 接口。

## 步骤一：建库 + 建表

### 1.1 建库

```bash
mysql -h YOUR_DB_HOST -u root -p -e "CREATE DATABASE IF NOT EXISTS jotlog DEFAULT CHARACTER SET utf8mb4 DEFAULT COLLATE utf8mb4_0900_ai_ci;"
```

或者直接跑 `scripts/init-db.sql`（它包含这条 + 版本自检）。

**账号**：默认用 root。`application.yml` 里 `JOTLOG_DB_USER` 默认值已改成 `root`。

> ⚠️ root 直连的代价：Jotlog 进程被攻破 = 攻击者拿到整个 MySQL 实例权限，
> 而不只是 jotlog 一个库。自用阶段可接受，但请确认这台MySQL 上没有别的业务库。
> 想收紧见 `init-db.sql` 里注释掉的建账号语句。

### 1.2 确认版本

```sql
SELECT VERSION(), @@ngram_token_size, @@character_set_server;
```

需要 `>= 8.0`、`ngram_token_size = 2`、`utf8mb4`。

**2026-10-07 已实测通过**：8.0.46 / 2 / utf8mb4，ngram 二字检索返回正确结果。
（`> Table 'jotlog.entries' doesn't exist` 属正常——表还没建，见下一步。）

### 1.3 建表（二选一）

**方式 A：让 Flyway 建（推荐）**

什么都不用做。启动应用时 Flyway 自动执行 `V1__init.sql`：

```powershell
$env:JOTLOG_DB_HOST="YOUR_DB_HOST"
$env:JOTLOG_DB_USER="root"
$env:JOTLOG_DB_PASSWORD="你的密码"
mvn spring-boot:run
```

启动日志里应出现 `Migrating schema` 或 `Successfully applied`。表就建好了。

**方式 B：手动建表**

想先验证 SQL、或Flyway 出问题时：

```bash
mysql -h YOUR_DB_HOST -u root -p jotlog < scripts/create-tables.sql
```

这个脚本建三张表并在末尾**自动跑一次验证**，末尾会输出：

```
FULLTEXT | title,ai_summary,raw_input
1 | 0.2276...   ← 灌入的测试数据被查到
```

看到这两行就算 SQL 没问题。

> 注意：Flyway 之后启动时会发现表已存在但没有迁移记录，
> 靠 `baseline-on-migrate: true` 兜住，不会报错。

## 步骤二：飞书后台配置

登录 <https://open.feishu.cn/>，进入你的企业自建应用。

### 2.1 开启机器人

「添加应用能力」→ 找到「机器人」→ 开启。

### 2.2 申请权限

「权限管理」→ 批量导入，粘贴：

```json
{
  "scopes": {
    "tenant": [
      "im:message",
      "im:message:send_as_bot"
    ]
  }
}
```

说明：
- `im:message` 用于接收你发给机器人的消息
- `im:message:send_as_bot` 用于回执，**没有它会收到消息但回不了复**

### 2.3 事件订阅

「事件与回调」→ 订阅方式选 **「使用长连接接收事件」**。

关键点：
- 选长连接后**不需要填回调地址**
- 不需要公网 IP
- 不需要配加密策略
- 保存后需要重新启动应用才会生效

然后「添加事件」→ 搜索 `im.message.receive_v1` → 添加。

### 2.4 发布

「版本管理与发布」→ 创建版本 → 发布。

**必须发布。** 只保存不发布，事件不会推给你。

### 2.5 拿凭证

「凭证与基础信息」→ 复制 `App ID` 和 `App Secret`。

`App Secret` 只显示一次，当场存好。

## 步骤三：本地跑

### 3.1 配环境变量

```powershell
# 数据库（你的 MySQL 在远程，注意要设 DB_HOST）
$env:JOTLOG_DB_HOST   = "YOUR_DB_HOST"
$env:JOTLOG_DB_USER   = "root"
$env:JOTLOG_DB_PASSWORD = "你的密码"

# 飞书（暂时没有就先跳过，步骤 3.4 再开）
$env:FEISHU_APP_ID     = "cli_你的AppID"
$env:FEISHU_APP_SECRET = "你的AppSecret"
```

> `JOTLOG_DB_HOST` 默认为 `127.0.0.1`。你的库在远程，**不设这个变量会连不上**。

### 3.2 打开飞书开关

`src/main/resources/application.yml` 里把

```yaml
jotlog:
  channel:
    feishu:
      enabled: false      # 改成 true
```

> **建议先不打开。** 保持 false 可以先验证"应用启动 → Flyway 建表 → API 可用"，
> 这几步跟飞书无关，先跑通再叠加变量，出问题时好定位。

### 3.3 启动（先不开飞书）

```powershell
mvn spring-boot:run
```

此时应看到 Flyway 日志：

```
Migrating schema `jotlog` to version `1 - init`
Successfully applied 1 migration
```

然后验证 API 活着：

```
curl http://localhost:8080/api/entries
curl http://localhost:8080/actuator/health
```

### 3.4 再开飞书

改 `enabled: true`，重启。**看到这两行就算长连接通了：**

```
飞书长连接启动中，appId=cli_xxx
connected to wss://xxx
```

## 步骤四：验收

### 4.1 发消息

在飞书里找到你的机器人，私聊发：

```
https://github.com/larksuite/oapi-sdk-go
这个看着不错
```

### 4.2 三个验收点

| 检查项 | 期望结果 |
|---|---|
| 飞书收到回执 | 立刻出现「已记下，稍后补全」 |
| 日志出现 | `已入库 id=1 type=REPO url=https://github.com/... 有附件=0` |
| 数据库有记录 | `SELECT * FROM entries;` 有一行，`entry_type = 'repo'` |

### 4.3 查数据库

```sql
USE jotlog;
SELECT id, entry_type, domain, raw_input, ai_status, created_at
  FROM entries ORDER BY id DESC LIMIT 5;
```

`raw_input` 应该完整保留你发的原文，包括那句"这个看着不错"。

### 4.4 测幂等

**幂等的键是飞书的 `message_id`，不是消息内容。** 这一点很容易搞错：

- **飞书重推**（网络抖动、我们处理超时）→ 同一个 messageId 再来一次 → 幂等命中，**不入库也不回执**
- **你手动再发一条一模一样的话** → 这是新消息，messageId 不同 → **会正常入库第二行**，这是对的

所以真正的幂等测试没法靠"再发一次"完成，只能看日志：

```sql
SELECT COUNT(*) FROM entries;   -- 正常使用时，这个数只增不重复
```

日志里出现「重复消息，跳过」就说明幂等生效了 —— 它只在飞书重推时出现。

> **代码与早期文档不一致的地方**（2026-10-08 确认）：
> 早期文档写「重复消息仍应回一条回执，回执不幂等是设计」，
> 但 `Pipeline.handle()` 里命中重复后是**直接 return，不发回执**。
> 以代码为准：重复消息不回执。理由也成立 —— 飞书重推是系统内部的事，
> 用户并没有再发一次，回一条回执反而让人莫名其妙。

为什么可以这样：如果回执也去重，第二次发消息时用户会收到
"什么都没发生"的沉默，用户会以为系统坏了。但飞书重推场景下用户根本没二次操作，
沉默才是正确的。

### 4.5 测中文全文检索

**这一步必须在服务已启动、`entries` 表已存在之后做。**

```sql
USE jotlog;

-- 灌一条
INSERT INTO entries (source, entry_type, raw_input)
VALUES ('selftest', 'note', '人生不是要赶到哪里去，而是要学会欣赏沿途的风景');

-- 二字词检索，应返回这一条。
-- ⚠️ MATCH 必须写全三列同序，否则报 1191。
-- ⚠️ 用 BOOLEAN 不用 NATURAL：NATURAL 有 50% 阈值，数据少时会静默返回 0 行。
SELECT id,
       MATCH(raw_input, title, ai_summary) AGAINST ('沿途' IN BOOLEAN MODE) AS score
  FROM entries
 WHERE MATCH(raw_input, title, ai_summary) AGAINST ('沿途' IN BOOLEAN MODE);

DELETE FROM entries WHERE source = 'selftest';
```

单字查询走应用层降级（`ngram_token_size=2` 查不到单字，这是设计）：

```
curl "http://localhost:8080/api/entries?q=人"
```

完整自检脚本在 `scripts/dbeaver-一键重建.sql`，包含索引验证 + 三组检索实测。

## 出问题时的排查顺序

| 现象 | 大概率原因 |
|---|---|
| `Table 'jotlog.entries' doesn't exist` | 正常，Flyway 还没跑。先 `mvn spring-boot:run` 建表 |
| `Communications link failure` | 没设 `JOTLOG_DB_HOST`，默认连的是 127.0.0.1 |
| `Access denied for user 'root'` | `JOTLOG_DB_PASSWORD` 没设或设错 |
| `Unknown database 'jotlog'` | 库没建，先跑步骤 1.1 |
| 启动就跳过飞书 | `enabled` 还是 false，或凭证为空 |
| 连上了但收不到消息 | 事件订阅没选长连接，或应用没发布 |
| 收到消息但没有回执 | 缺 `im:message:send_as_bot` 权限 |
| 群里发消息没反应 | `mention-only=true` 但没 @ 机器人 |
| 消息重复入库 | `source_msg_id` 没取到，检查日志里 messageId 是否为空 |
| 搜中文没结果 | 索引建的时候漏了 `WITH PARSER ngram`（静默失效） |
| 搜中文没结果但索引看着没问题 | 用了 `NATURAL LANGUAGE MODE` → 50% 阈值把词当停用词丢了。**改用 `IN BOOLEAN MODE`**（应用层已改） |
| **搜「Java」这类英文词没结果** | ngram 丢了含 `a`/`i` 的 token。`Java`→`Ja/av/va` 全含 a 全被丢。**执行 `SET GLOBAL innodb_ft_enable_stopword=0` 并重建索引**，且要写进 `my.cnf`。详见 `scripts/init-db.sql` |
| `1191 Can't find FULLTEXT index` | `MATCH` 的列与索引定义不一致。**必须写全三列同序**：`MATCH(raw_input, title, ai_summary)`。修复见 `scripts/fix-fts-1191.sql` |
| `Unsupported character encoding 'utf8mb4'` | JDBC URL 里 `characterEncoding` 只能写 **`UTF-8`**，不能写 `utf8mb4`（那是 MySQL 字符集名，Java 里没这个 charset） |
| `1290 innodb_ft_min_token_size` | 未触发 ngram，检查 `@@ngram_token_size` 是否被改过 |
| 连接断 | 网络问题，SDK 自带重连，看日志确认 |

看日志：

```powershell
mvn spring-boot:run | Select-String "jotlog|lark"
```
