# Jotlog 前端界面设计

> 2026-10-08。v0.2 的前端骨架能跑通之后做的一轮重写：从"一套 720px 居中列 + 手机底部 tab"，
> 改成真正同时服务手机和电脑的三档布局，并补齐深色模式、详情面板、骨架屏这些缺失的部分。
>
> 这一篇只讲界面。登录流程和接口见 [鉴权与前端](Jotlog-鉴权与前端.md)。

---

## 一、三档布局

同一份 DOM，靠两个断点切换。断点只有两个，因为布局只需要回答两个问题：

| 宽度 | 侧栏 | 内容 | 详情 | 输入入口 |
|---|---|---|---|---|
| `< 768`（手机） | 无 | 顶栏 + 全宽单列 | 底部 sheet | 右下角悬浮按钮 → 底部弹层 |
| `768–1279`（平板 / 小窗） | 68px 窄轨（只有图标） | 760px 居中单列 | 右侧抽屉 | 时间线顶部常驻输入框 |
| `≥ 1280`（桌面） | 248px 完整侧栏 | 760px 单列 + 右侧详情栏 | **常驻右栏，不遮挡列表** | 时间线顶部常驻输入框 |

**为什么是 1280 才让详情常驻**：右栏 380px + 侧栏 248px = 628px。在 1024 屏上剩下不到 400px 给列表，
一条随手记只能显示四五个字，那就不是"两栏"而是"两个都很挤"。1280 是双栏真正成立的起点。

**为什么整屏用 `100dvh` 而不是 `100vh`**：手机浏览器地址栏收起/展开会让 `100vh` 抖动，页面高度跟着跳。
`dvh` 跟着可视高度走。滚动条只出现在内容列上，侧栏和导航永远固定。

**为什么详情面板在宽屏内联、窄屏走抽屉**：两种形态的 DOM 结构不一样（一个是 grid 的一列，一个是 Teleport 出去的覆盖层），
靠 `display:none` 切换会同时渲染两份，且状态不好同步。用 JS 断点判断（`useBreakpoint`）决定渲染哪个，
代价是多一个 matchMedia 监听，换来的是只有一份真实 DOM。

## 二、设计系统

### 纸感编辑风

暖白纸底 + 墨色文字 + 衬线体日期。刻意避开通用 SaaS 审美（蓝紫渐变、纯白套娃卡片、全圆角 + 大投影），
因为这是"给自己看的本子"，不是给老板看的仪表盘。

主色只有墨绿一个，不搞渐变。星标用铜色 —— 它是"我特别标出来的"，不该和主色抢注意力。

### token 分三层

```
--j-paper / --j-ink / --j-accent ...   ← 语义变量，浅深两套，只在 style.css 里定义
        ↓ @theme inline
--color-paper / --color-ink ...        ← 接进 Tailwind，生成 bg-ink / text-accent 这类 utility
        ↓
class="text-ink-3 bg-accent-soft"      ← 组件里只写语义类名，不写色值
```

**组件里禁止出现 `#xxx` 和 `bg-white`。** 一旦写死，深色模式就是逐个文件去改，而且永远改不干净。

### 深色模式的实现要点

浅色和深色**不是同一套颜色的明暗翻转**，而是两套分别调过的色板：

- 深色底用偏暖的黑褐（`#131311`）而不是纯黑 —— 纯黑配暖白文字像终端，不像本子
- 深色下的墨绿是**重新选的**（`#1f4f46` → `#79b3a4`），不是把浅色的加深（加深后几乎看不见）
- 深色下的投影要更重（浅色里靠亮边分离层次，深色里只能靠影）

技术上有个坑必须记住：

```css
/* ❌ 这样写，深色覆盖不生效 */
@theme { --color-paper: #fbfaf7; }
.dark  { --color-paper: #131311; }   /* utility 里已经把值内联成静态的了 */

/* ✅ 必须 inline：utility 生成 var(--j-paper)，值跟着 .dark 变 */
@theme inline { --color-paper: var(--j-paper); }
:root { --j-paper: #fbfaf7; }
.dark { --j-paper: #131311; }
```

深色模式用 **class 策略**（`@custom-variant dark`），不是 `prefers-color-scheme`：
用户要能在设置里选"跟随系统 / 浅色 / 深色"。只靠媒体查询做不出"我就要浅色，系统爱怎么设怎么设"。

**防闪烁**：主题必须在首帧之前定好，所以 `index.html` 里有一段内联脚本读 localStorage 直接给 `<html>` 加 class。
放在 `main.ts` 里来不及 —— 那段 JS 要等模块下载完才跑。

## 三、组件职责

| 组件 | 职责 |
|---|---|
| `AppShell.vue` | 三档布局骨架、URL ↔ 选中态同步、快捷键注册、悬浮按钮 |
| `SideNav.vue` | 侧栏。一份组件覆盖窄轨 / 完整两档（靠 `collapsed` prop，不拆两个组件） |
| `MobileTopBar.vue` | 手机顶栏：当前页标题 + 搜索 + 用户菜单 |
| `MobileTabBar.vue` | 手机底栏：四项（设置移到了头像菜单里，低频动作不占底部 20% 宽度） |
| `EntryCard.vue` | 列表里的一条。选中态、hover 操作、关键词高亮 |
| `EntryDetailPanel.vue` | 详情内容本体。不知道自己被放在侧栏还是抽屉里 |
| `EntryDetailOverlay.vue` | 详情的覆盖层容器（手机底部 sheet / 平板右侧抽屉） |
| `ComposeBox.vue` | 桌面常驻输入框，带类型预览（粘贴链接时提示会被记成什么） |
| `ComposeSheet.vue` | 输入弹层，手机上从底部升起 |
| `TypeBadge` / `EmptyState` / `SkeletonList` / `ToastHost` / `UserMenu` | 通用件 |

### 列表卡片的操作区

- 手机端**只留星标**。归档和删除移到详情面板 —— 那里有完整信息，不容易误点。
- 桌面 hover 才出现（`group-hover`），但**选中时和键盘聚焦时要能看见**（`group-focus-within`），
  否则只用键盘的人根本操作不了。
- 删除是就地二次确认，3 秒不点自动收起。不用原生 `confirm()`：它会打断整个页面，且样式跟应用完全无关。

## 四、状态管理

三个 store，分工明确：

| store | 放什么 | 为什么 |
|---|---|---|
| `auth` | token、当前用户 | 全局唯一 |
| `ui` | 选中哪条、弹层开没开 | 跨组件共享，和服务器无关 |
| `stats` | 顶部那排数字 | 侧栏和时间线都要显示，各拉一次会打架 |

**条目列表数据刻意不上提到全局。** 时间线和搜索是两个视图，共享一份列表会让切标签时互相污染。
视图自己持有自己的 `items`，跨视图的变更靠"广播"同步（见下）。

### 三个计数器

跨组件的"信号"一律用**递增的数字**而不是布尔量：

| 计数器 | 谁发 | 谁收 | 解决什么 |
|---|---|---|---|
| `composeFocusSeq` | 侧栏"记一笔"、快捷键 `n` | `ComposeBox` | 点第二下时布尔值没变，watch 不触发 |
| `reloadSeq` | 手机弹层里记完一条 | 列表视图 | 弹层和列表不在同一棵组件树，传不了事件 |
| `entryChange` | 详情面板（挂在 AppShell 上） | 列表视图 | 面板改了一条，列表要跟着改 |

`entryChange` 带 `{id, kind, starred?, archived?}`，由接收方自己决定怎么跟。
这比"把列表数据也提到全局"要好：共享状态意味着两个视图的筛选条件会互相打架。

## 五、交互约定

### 键盘

`/` 搜索 · `n` 记一笔 · `j/k` 上下移动 · `Esc` 关闭 · `Ctrl+Enter` 直接记下。

一律判断"焦点在输入框里就不抢键" —— 正在打字时想输入字母 `n` 的人不在少数。

### 手机上的克制

- **不自动聚焦输入框。** 键盘一上来顶掉半个屏幕，用户还没决定写什么就被弹上来了。
- **底栏四项而不是五项。** 设置移到头像菜单，它是低频动作。
- **底部 sheet 不做真拖拽。** 拖动手势和内部滚动的冲突处理，比它带来的价值麻烦得多，
  只在顶部放一根小横条提示"这是可以关掉的面板"。

### 加载与空状态

- 首屏用**骨架屏**而不是转圈。转圈让人以为在等一个"过程"，骨架屏让人知道"内容马上就在这个位置出现"。
- 骨架屏的宽度**用固定序列不用随机数**。随机数每次渲染都变，看起来像在闪，比转圈更烦。
- 空状态要**说清楚这儿为什么是空的**，而不是只放一个图标。

### 安全底线

搜索结果要高亮关键词，但**高亮必须走分段渲染，不能用 `v-html` 拼 `<mark>`**。
一条含 `<script>` 的随手记就能执行脚本，而这个应用的 token 就存在 localStorage 里。
见 `utils/highlight.ts`。

## 六、踩到的坑

| 坑 | 现象 | 解法 |
|---|---|---|
| `@theme` 不加 `inline` | 深色模式完全不生效，且不报错 | 见第二节 |
| `manifest.webmanifest` 里写注释 | 严格 JSON，PWA 直接装不上 | 注释只能写在旁边的 md 里 |
| 改了前端没动 sw 版本号 | 已装 PWA 的用户拿到旧资源 | 改任何被缓存的资源就 +1 |
| `orientation: "portrait"` | 桌面 PWA 窗口被强行竖过来 | 改成 `any` |
| `new Date(iso).toISOString()` | MySQL 的 LocalDateTime 没有时区后缀，早上八点前会算成昨天 | 本地时间手工拼串，见 `todayIso()` |
| 时间线统计用 `stats.total` 做增量 | 后端 `total` 只统计未归档的 | 归档 / 取消归档要同时改 `total` 和 `archived` |
| 分组日期用 `sticky` | 滚动容器是内容列不是 window | `sticky` 相对最近的滚动祖先，正常生效；`scrollBehavior` 才管不到它 |
| IntersectionObserver 无限滚动 | 滚动发生在内层容器 | 默认 root 是视口，仍然有效，不用改 |

## 八、内容本位改造（2026-10-09）

这轮解决的是"所有类型长得一样"的问题：列表原来是"数据库行视图"，一条图和一段话渲染成同一个样子。改完的原则只有一条——**内容以它本来的样子出现**。

### 列表卡片

| 内容 | 列表表现 |
|---|---|
| 带图的条目 | 右侧 64px 缩略图（`imageSha` 聚合列），扫一眼就知道哪条是图 |
| 带文件的条目 | "N 个附件" chip（`attachmentCount` 减去图片数，不重复报） |
| Markdown 正文 | 预览先过 `plainPreview()` 剥符号 —— 扫读要的是"写了什么"，`#` 和 `**` 全是噪音 |

### Markdown 渲染（自研，零依赖，零 v-html）

`utils/markdown.ts` + `MarkdownView.vue`。三个决策：

1. **不用 marked + DOMPurify + v-html**：token 在 localStorage，渲染用户输入的第一原则是 DOM 里不许有拼接的 HTML 字符串。解析成 token 树用 `h()` 渲染，安全是结构保证的。
2. **保守解析**：配对失败的语法一律原样保留。宁可少渲染一个标题，不能把用户原话改得面目全非（原文不可变是红线）。链接协议白名单 http/https/mailto，`javascript:` 在解析层就死掉。
3. **详情页默认渲染、原文一键切换**：检测到 md 语法（`looksLikeMarkdown`，保守启发式）才渲染；切换不持久化——渲染是展示层的 courtesy，原样才是产品的承诺。

### 附件链路（这次打通的最后一公里）

- 后端列表查询加两个关联子查询列：`image_sha`（首图）、`attachment_count`，前端一次请求拿全摘要。
- `GET /api/attachments/{sha}/raw`：sha 校验 64 位 hex、落盘路径 normalize 后必须在存储根内（防 DB 污染）、**inline 白名单**——`text/html` 和 `image/svg+xml` 强制 octet-stream 下载，svg 能带 script，绝不在站点域内渲染。
- **图片不能直接 `<img src>`**：img 发不了 Authorization 头（token 在 localStorage）。走 `attachmentCache.ts` 的 fetch → blob → objectURL 链路，带 LRU（60 张）+ in-flight 去重 + IntersectionObserver 懒加载（列表 30 条不等于 30 个原图请求）。
- Lightbox：黑底全屏、Esc/左右键、点击关闭；图源优先命中 attachmentCache，详情页看过的图秒开。

### 顺手修掉的两个存量问题

| 问题 | 后果 | 修复 |
|---|---|---|
| `createEntry` 用 query string 传正文 | 长笔记被 URL 长度上限（2-8KB）**悄悄截断**，用户以为存全了 | 改 JSON body（前后端同步） |
| `StorageProperties` 在 config/ 目录但 package 是 core | clean 构建必炸（之前被 target 增量缓存掩盖）；`IngestService` 同包引用依赖着这个错位 | package 归位 config，IngestService 补 import |

另：`src/main/resources/application-local.yml` 的 Windows 只读位会让 Maven 复制出的 target 副本也只读，构建反复报"拒绝访问"——`attrib -R` 掉了，若重新设只读请记得构建会再次失败。
